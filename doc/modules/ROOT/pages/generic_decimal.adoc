== 3.2.8 Note
In the event of binary arithmetic between an integer type and a decimal type the integer is converted to the decimal type first, and the result will be returned as the same type as the decimal operand. (e.g. decimal32_t * uint64_t -> decimal32_t)
A comparison with an integer does not convert the integer, see xref:generic_decimal.adoc#operator_behavior[the comparison operators].

In the event of binary arithmetic between two decimal types the result will be the higher precision type of the two (e.g. decimal64_t + decimal32_t -> decimal64_t)

A compound assignment with another decimal type computes the binary operation in that higher precision type, and then converts the result to the type of the left operand (e.g. `d32 += d64` assigns `static_cast<decimal32_t>(d32 + d64)`).

An exact result of `decimal32_t`, `decimal64_t` or `decimal128_t` arithmetic has the exponent that IEEE 754 prefers, or the nearest exponent that holds all its digits.
That exponent is the smaller exponent of the operands for `+` and `-`, the sum of the exponents for `*`, and their difference for `/`.
The rule uses an integer operand after its conversion: an integer of at most the precision of the type has exponent 0, and a wider integer is rounded to that precision.
A finite inexact result that is not subnormal has all the digits of the type.
A subnormal result can have fewer digits, and an inexact result can underflow to zero or overflow to infinity.
The exponent does not change the value, but `quantexp` shows it:

[source, c++]
----
quantexp(decimal32_t{15, -1} + decimal32_t{1}); // -1, the sum is 2.5
quantexp(decimal32_t{1} / decimal32_t{4});      // -2, the quotient is 0.25
quantexp(decimal32_t{1} / decimal32_t{1});      // 0, the quotient is 1
quantexp(decimal32_t{2} / decimal32_t{3});      // -7, the quotient is 0.6666667
quantexp(decimal32_t{1234567, 1} - 12345670);   // 1, the integer converts to 1234567e1
quantexp(decimal32_t{0, 5} * 12345670);         // 6, the same converted exponent of 1
----

== 3.2.11 Note

`operator<<` uses the stream flags as for a `double`: the float field (`fixed`, `scientific` or `hexfloat`), the precision, `showpos`, `showpoint`, `uppercase`, the width, fill and adjustment, and the grouping and decimal point of the `std::numpunct` of the stream character type. An exception during the output sets `badbit`, and goes to the caller only when `badbit` is in the exception mask.

[#operator_behavior]
== Operator Behaviors

=== Unary Plus

[source,c++]
----
// 3.2.7 unary arithmetic operators:
constexpr decimal32_t  operator+(decimal32_t rhs) noexcept;
constexpr decimal64_t  operator+(decimal64_t rhs) noexcept;
constexpr decimal128_t operator+(decimal128_t rhs) noexcept;
----

Returns `rhs` unmodified in all cases.

=== Unary Minus

[source,c++]
----
constexpr decimal32_t  operator-(decimal32_t rhs) noexcept;
constexpr decimal64_t  operator-(decimal64_t rhs) noexcept;
constexpr decimal128_t operator-(decimal128_t rhs) noexcept;
----

Returns negated `rhs` in all cases.

=== Addition

[source,c++]
----
// 3.2.8 binary arithmetic operators:
// LHS and RHS can be any integer or decimal type

constexpr /* see 3.2.8 */ operator+(LHS lhs, decimal32_t rhs) noexcept;
constexpr /* see 3.2.8 */ operator+(LHS lhs, decimal64_t rhs) noexcept;
constexpr /* see 3.2.8 */ operator+(LHS lhs, decimal128_t rhs) noexcept;
constexpr /* see 3.2.8 */ operator+(decimal32_t lhs, RHS rhs) noexcept;
constexpr /* see 3.2.8 */ operator+(decimal64_t lhs, RHS rhs) noexcept;
constexpr /* see 3.2.8 */ operator+(decimal128_t lhs, RHS rhs) noexcept;
----

Returns the result of `lhs + rhs` subject to:

. If either `lhs` or `rhs` are `NAN`, returns `QNAN`
. If `lhs` and `rhs` are `INF` of opposite sign, returns `QNAN`
. If either `lhs` or `rhs` are `INF`, returns `INF` of same sign
. If `lhs + rhs` overflows, returns `INF`
. If `lhs + rhs` underflows, returns `0`

. If either `lhs` or `rhs` are `NAN`, returns `QNAN`
. If `lhs` and `rhs` are `INF` of opposite sign, returns `QNAN`
. If either `lhs` or `rhs` are `INF`, returns `INF` of same sign
. If `lhs - rhs` overflows, returns `INF`
. If `lhs - rhs` underflows, returns `0`

. If `lhs * rhs` overflows, returns `INF`
. If `lhs * rhs` underflows, returns `0`

constexpr /* see 3.2.8 */ operator/(decimal128_t lhs, RHS rhs) noexcept;

Returns the result of `lhs / rhs` subject to:

. If either `lhs` or `rhs` are `NAN`, returns `QNAN`
. If `lhs` is `INF`:
.. Returns `QNAN` if `rhs` is `INF`
.. Returns `INF` if `rhs` is not `INF`
. If `rhs` is `0` returns `INF`
. If `rhs` is `INF` returns `0`
. If `lhs / rhs` overflows, returns `INF`
. If `lhs / rhs` underflows, returns `0`

Returns the result of the comparison subject to:

. If `lhs` or `rhs` returns `false`
.. This includes the case where both `lhs` and `rhs` are `NAN`

A comparison with an integer compares the exact values, and does not convert the integer to the decimal type first.
An integer with more digits than the decimal type can then differ from each value of that type:

[source, c++]
----
decimal32_t{10000000} == 10000001;                           // false
decimal32_t{10000000} < 10000001;                            // true
decimal32_t{10000000} == static_cast<decimal32_t>(10000001); // true, the conversion rounds
----
